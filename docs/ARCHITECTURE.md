# CarCheck — Architecture

Owner: architecture. Product truth: `docs/BRIEF.md`. Detailed designs live elsewhere: data model → `docs/DATA_MODEL.md`, image pipeline → `docs/IMAGE_PIPELINE.md`, flows → `docs/UX_FLOWS.md`, visual language → `DESIGN.md`. This file fixes the stack, the seams between those areas, and how the app is built and verified.

## 1. Decisions at a glance

- **Expo SDK 57** (latest stable; SDK 58 is in preview): React Native 0.86.3, React 19.2.3, Hermes, New Architecture (mandatory since RN 0.82). Android 7+ (minSdk 24), target/compile SDK 36; iOS 16.4+.
- **Continuous Native Generation**: `android/` and `ios/` are generated by `expo prebuild` and never committed. All native config lives in `app.config.ts` and `plugins/`.
- **TypeScript 6 strict**, path alias `@/` → `src/`.
- **Offline by construction**: no backend, no network code, and the release APK has no INTERNET permission (section 6).
- **APKs are built on GitHub Actions** (section 8). No local Android SDK is required for day-to-day work.

## 2. Stack

All Expo-managed versions come from `npx expo install` (the `bundledNativeModules` of expo@57.0.24). `npx expo install --check` reports up to date, and `npx expo-doctor` passes 21/21.

## 3. Rejected alternatives

- **react-native-vision-camera 5.x**: it has the best control (tap-to-focus, formats), but v5 is a full rewrite from April 2026 and pulls in `react-native-nitro-modules` and `react-native-nitro-image`. Revisit it behind the camera seam if device tests show focus problems.
- **drizzle-orm**: typed queries are nice, but 1.0 (RC) is changing its migration format and it adds drizzle-kit plus `.sql` bundling. We need hand-controlled migrations that also run on a restored DB before the swap.
- **fflate / JSZip for backups**: every photo byte would cross the JS heap, and CRC32 would run in Hermes (no JIT). With hundreds of MB this is slow and prone to running out of memory.
- **Zip for "share all images"**: phone recipients (WhatsApp, mail) cannot preview a zip inline. Zip stays for backups and "export originals".
- **react-native-view-shot for evidence images**: the output depends on screen density and on-screen layout. Skia offscreen renders deterministically at a fixed pixel size.
- **pdf-lib / native PDF builders**: HTML/CSS through expo-print is far cheaper for a text-heavy report. Revisit only if exact pagination control becomes necessary.
- **Media-library access for imports**: ID documents, the vehicle photo and the logo come in through `expo-image-picker`'s system photo picker (Android Photo Picker / iOS PHPicker), which needs no media permission. Its iOS behaviour must be checked on a device in the iOS phase; if a permission prompt appears, add the plugin with a `photosPermission` string. `expo-document-picker` is used only to pick a `.carcheck` backup file.
- **zustand / redux / react-query**: not needed (section 5).
- **Flutter / native Kotlin**: would lose the single TypeScript codebase for Android and iOS.

## 4. Folder structure

```
app/                 expo-router routes only. Screens compose src/ui and src/features; no SQL.
src/
  domain/            Pure TS: entities, value types, rules (rental lifecycle, contract template and
                     variable registry, damage labels). No React, no Expo imports. Unit-tested in Node.
  data/              SQLite connection, migrations, repositories, file store, backup/restore.
  media/             Pixels: camera wrapper, photo processing, geometry, marker editor, compare
                     views, Skia evidence composition. May use src/ui tokens and primitives.
  documents/         Leaving the app: HTML builders, PDF (expo-print), share (single/multi), print.
  features/<area>/   Screen-level services and components shared by a few routes (inspection,
                     damage, contract, evidence, report, entities, settings). They orchestrate
                     data + media + documents (e.g. contract PDF generation, capture saving).
  ui/                Design system: tokens, primitives, shared components.
  config.ts          App constants.
plugins/             Local Expo config plugins (run at prebuild only).
.github/workflows/   CI APK build.
```

**Dependency direction:** `domain` ← `data` ← `features` ← `app`; `media` and `documents` sit beside `data` and are used by `features` and `app`; `ui` is used by everything that renders (including `media`). `domain` imports nothing else from the app. Only `src/data` touches expo-sqlite. File IO lives in `src/data` (the store), `src/media` (photos) and `src/documents` (exports); `src/features` may call them. Tests live in `__tests__/` next to the code. The layering is not lint-enforced yet (`no-restricted-imports` is the tool when it is).

## 5. State and data access

- **Source of truth = SQLite plus files.** There is no global client store.
- **Repositories** are plain TS functions or classes that take a small `SqlExecutor` interface (the subset of expo-sqlite's async API we use). Jest can then run the same code against Node's built-in `node:sqlite`. Verified: `node:sqlite` works under jest-expo with a `/** @jest-environment node */` docblock. Tests that import it need `@types/node` (not yet installed).
- **Screens** read through small hooks such as `useQuery(fn, deps)`. They re-run on a lightweight "data changed" event emitted by repository writes; expo-sqlite's `addDatabaseChangeListener` is an alternative. The DB is provided once in `app/_layout.tsx`, which runs migrations before first render.
- **Flow-scoped state** (for example an in-progress inspection) lives in a React context owned by the flow's layout route. Add zustand only if this becomes painful.
- **Migrations**: an ordered TS array keyed by `PRAGMA user_version`, each step run in a transaction. The same runner migrates a restored DB copy *before* it replaces live data. DATA_MODEL.md owns the details.

## 6. Storage, privacy, offline enforcement

- All data lives under `Paths.document` (app-private, invisible to the gallery and media store). Temporary exports go under `Paths.cache/exports/…` and are swept on app start (older than 24 h). Native-module caches (`Camera/`, `ImagePicker/`, `ImageManipulator/`) are swept after 1 h.
- The DB stores **relative** paths only. Absolute sandbox paths change across iOS reinstalls, restores and backups.
- `android.allowBackup: false` keeps customer IDs and signatures out of Google auto-backup. Android 12+ device-to-device transfer is still possible, since the owner starts it. In-app backup is the supported path.
- **Permissions:** CAMERA (plus VIBRATE from the template, and DETECT_SCREEN_CAPTURE from expo-screen-capture). Blocked: RECORD_AUDIO, READ/WRITE_EXTERNAL_STORAGE, SYSTEM_ALERT_WINDOW, and READ_MEDIA_IMAGES (declared by expo-screen-capture for screenshot detection below Android 14, which CarCheck does not use). DETECT_SCREEN_CAPTURE must stay: on Android 14+ the module registers a screen-capture callback as soon as it loads, and without the permission the app crashes at launch (install-time permission, no prompt, no data access). CI fails if it is missing. expo-camera's ML Kit barcode scanner is disabled, which removes a Play Services dependency that can download models.
- **Release APK has no network:** `plugins/withReleaseOffline.js` writes `android/app/src/release/AndroidManifest.xml`, which removes INTERNET and ACCESS_NETWORK_STATE. Debug and dev-client builds keep INTERNET for Metro. CI fails the build if the release APK requests INTERNET or ACCESS_NETWORK_STATE (`aapt dump permissions`). If expo-print's WebView misbehaves on a device, drop the plugin line in `app.config.ts`.
- **Sharing:** react-native-share's FileProvider exposes only `cache/` and `Download/`. Always copy files into `cache/exports/` before sharing, and never share from `documents/`. expo-sharing's share-into-app plugin is deliberately not enabled.
- `react-native-share` and `react-native-zip-archive` are not in Expo Go. Import them lazily inside `src/documents` / `src/data/backup` functions, so the rest of the app still runs in Expo Go.

## 7. Seams for camera, composition and PDF (details: IMAGE_PIPELINE.md)

- **Camera:** wrap `CameraView` in `src/media/camera` so a VisionCamera swap touches one module. Choose the largest 4:3 size from `getAvailablePictureSizesAsync()`. Captures land in cache; move them into the file store immediately. Lay the preview out at the photo aspect so the ghost overlay (a sibling `expo-image` with opacity) matches what is captured. expo-camera has **no tap-to-focus on Android** (continuous AF only; `autofocus` is iOS-only).
- **Volume-key shutter** (UX_FLOWS) needs a third-party native module (for example `react-native-volume-manager` 2.2). It is **not installed**; decide after the first device test.
- **Skia offscreen:** decode with `Skia.Data.fromURI` → `Skia.Image.MakeImageFromEncoded`, draw on `Skia.Surface.MakeOffscreen(w, h)`, then `makeImageSnapshot().encodeToBytes(JPEG, 85)` → `File.write`. Pre-scale inputs to the target size with image-manipulator, because a decoded 12 MP photo is about 48 MB.
- **PDF:** expo-print renders HTML in a WebView. Embed images as base64 data URIs rather than `file://` URLs, and keep evidence JPEGs sized per the pipeline spec so the HTML stays bounded. The final PDF is moved from cache into the file store.

## 8. Building APKs

### 8.1 GitHub Actions (primary): `.github/workflows/android-apk.yml`

Triggers are a push to `main`/`master`, or manual **Run workflow** with inputs `variant` (release | debug) and `abis`. Steps:

1. `npm ci` on Node 24, then `npm run verify` (tsc + eslint + jest). A red check stops the build.
2. `npx expo prebuild --platform android --no-install` generates `android/`. This applies `app.config.ts` and the plugins, including release-offline.
3. On Temurin JDK 17 with Gradle cached (`setup-gradle`, basic provider), run `./gradlew assembleRelease -PreactNativeArchitectures=armeabi-v7a,arm64-v8a`. Dropping the x86 emulator ABIs roughly halves build time and APK size.
4. **Signing.** If `ANDROID_KEYSTORE_BASE64` exists, the keystore is decoded to `$RUNNER_TEMP`. Signing uses AGP's `-Pandroid.injected.signing.*` properties, so no Gradle files are patched. Otherwise the template's release→debug signingConfig applies. That APK is installable but signed with the **public** debug key and named `…-debugsigned.apk`, and the job logs a warning.
5. `apksigner verify --print-certs` logs the signer. With a release key, the job **fails** unless the signer SHA-256 equals the keystore's, so a silent fallback is impossible.
6. The APK is uploaded as an artifact named `carcheck-<version>-<run>-<release|debugsigned|devclient>.apk` (30-day retention). `versionCode` = the GitHub run number, so each build installs over the previous one.

Download it from the run's **Artifacts**, copy it to the phone, open it, and allow "install unknown apps".

**Repo secrets:** `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and optionally `ANDROID_KEY_PASSWORD` (defaults to the store password, which is normal for PKCS12). Create the keystore once, on a trusted machine, never inside the repo:

```sh
keytool -genkeypair -v -storetype PKCS12 -keystore carcheck-release.jks -alias carcheck \
  -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=CarCheck"
# PowerShell: [Convert]::ToBase64String([IO.File]::ReadAllBytes("carcheck-release.jks")) | gh secret set ANDROID_KEYSTORE_BASE64
base64 -w0 carcheck-release.jks | gh secret set ANDROID_KEYSTORE_BASE64
gh secret set ANDROID_KEYSTORE_PASSWORD
gh secret set ANDROID_KEY_ALIAS --body carcheck
```

**The signing key is permanent.** Android refuses an update signed by a different key. The only way out is to uninstall, which **deletes all local data**. So:

- Set up the release key before the first agency install.
- Never hand out `debugsigned` APKs.
- Keep two offline copies of the `.jks` file and its passwords.
- For the Play Store later, upload this same key as the Play App Signing key so side-loaded installs can update from Play.

**Dev loop without an Android SDK:** run the workflow once with `variant=debug`, which builds a dev-client APK with INTERNET kept and no signing needed. Install it, then run `npm start` on the PC on the same Wi-Fi and open the URL/QR in the app. JS changes then hot-reload. Rebuild only when native dependencies or `app.config.ts` change. `npm run start:go` (Expo Go) also works for screens that don't use zip or multi-share.

If Gradle runs out of memory on a small private-repo runner, raise `org.gradle.jvmargs` (currently `-Xmx2048m`) through a config plugin.

### 8.2 Local build (optional; needs the Android SDK)

- JDK 17 (the RN Gradle plugin uses `jvmToolchain(17)`; Gradle 9.3.1).
- Android SDK command-line tools plus `platform-tools`, with `ANDROID_HOME` set and `sdkmanager --licenses` accepted. AGP then downloads `platforms;android-36`, `build-tools;36.0.0`, NDK `27.1.12297006` and CMake on demand.
- Run `npm run prebuild`, then `cd android && gradlew assembleRelease`, or `npx expo run:android` for a debug build on a USB device.
- On Windows, keep the repo path short (native CMake builds hit the 260-character limit) and enable long paths.
- Sign locally with the same injected `-Pandroid.injected.signing.*` properties.

### 8.3 EAS Build (alternative)

Add an `eas.json` profile with `"android": { "buildType": "apk" }` and run `npx eas-cli build -p android --profile preview`. This needs an Expo account and builds in Expo's cloud; the app itself stays offline. If EAS generates the keystore, download it: GitHub and EAS builds must share one key. `eas build --local` does not run on Windows.

## 9. iOS readiness (not built yet)

- `bundleIdentifier` is `com.carcheck.app`. `NSCameraUsageDescription` comes from the expo-camera plugin, and the microphone key is removed. `NSPhotoLibraryAddUsageDescription` is set, because "Save Image" in the share sheet crashes without it. `ITSAppUsesNonExemptEncryption` is false.
- `Paths.document` is included in iCloud/device backups by default. Before App Store release, decide whether to exclude it (`NSURLIsExcludedFromBackupKey`, via a small module) or move data to Library/Application Support.
- Relative paths in the DB (section 6) make sandbox UUID changes harmless.
- expo-print uses WKWebView on iOS. Test page size and margins on both platforms.
- Multi-file share and zip (minizip) both have native iOS paths. Orientation is unlocked, and `supportsTablet` is true.
- Building needs a Mac with Xcode 26.4+ or EAS Build. The minimum is iOS 16.4.

## 10. Verification strategy

| Check | Command | Where |
|---|---|---|
| Types | `npm run typecheck` (`tsc --noEmit`) | local + CI |
| Lint | `npm run lint` (`expo lint`, flat config) | local + CI |
| Unit tests | `npm test` (jest-expo preset; `@/` alias mapped from tsconfig) | local + CI |
| All three | `npm run verify` | local + CI |
| Dependency alignment | `npx expo install --check`, `npx expo-doctor` | local, on every dependency change |
| Native config | `npx expo prebuild -p android --no-install`, inspect `android/`, then delete it | local, no SDK needed |
| Release build and signing | GitHub Actions workflow | CI |

- **Testable without a device:** domain rules, SQL and migrations (via `node:sqlite`), geometry and layout math, contract templating, backup manifest validation.
- **Device only:** camera capture and framing, Skia rendering output, PDF appearance, share and print sheets, zip on large data, orientation, and memory/performance on a low-end phone. These belong in a manual test checklist per release.
- TypeScript 6 no longer auto-includes `@types/*`, so `tsconfig.json` lists `"types": ["jest"]`. Add `"node"` together with `@types/node` when data tests need `node:sqlite`.

## 11. Watch list

- Upgrade only with `npx expo install expo@^58 --fix`. Do not bump Skia, Reanimated or Worklets outside the SDK pins (Skia latest is 2.12; SDK 57 pins 2.6.2).
- react-native-zip-archive and react-native-share are the only non-Expo native modules. They are pinned with `~`; re-check them on every SDK upgrade.
- `android.injected.signing.*` is an AGP IDE contract, not a public DSL. The CI fingerprint check catches it if AGP ever stops honouring it.
